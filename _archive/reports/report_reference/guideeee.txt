### PHASE 1: HIGH-LEVEL OVERVIEW

**What EDITEASE Does**
EDITEASE is an AI-assisted video ingestion, classification, and organization platform. It takes raw video uploads, breaks them down into semantic "scenes" using computer vision, analyzes each scene for its type (e.g., action, interview) and dominant human emotion, and automatically organizes these clips into a library where they can be reviewed, edited, and exported.

**The Problem it Solves**
Video editors spend countless hours manually reviewing raw footage, cutting it into usable clips, tagging the contents, and organizing it into folders. EDITEASE automates this grueling "logging" phase using AI, turning unstructured raw video into a fully searchable, structured database of ready-to-edit clips.

**The Overall Architecture**
It is a modern web application built on decoupled architecture:
1. **Frontend:** React + Vite SPA (Single Page Application) handling file uploads, user dashboards, and the clip review interface.
2. **Backend/API Layer:** Python Flask serving as the REST API for user authentication, fetching database records, and launching async jobs.
3. **Task Queue:** Celery with Redis broker for running heavy video processing tasks entirely in the background without blocking the main API.
4. **Data Layer:** MongoDB for storing unstructured JSON metadata (scene vectors, labels, confidence scores) and Cloudinary as the cloud blob storage for actual `.mp4` video files and `.jpg` thumbnails.

**End-to-End Workflow**
1. **Upload:** User uploads a video (`.mp4`) via the React frontend.
2. **Ingestion & Queuing:** The Flask API (`media_bp`) accepts the video, secures it locally, and fires a background Celery task.
3. **Pipeline (The AI Core):** The background worker runs `process_video()`. It cuts the video into scenes, generates thumbnails, identifies faces, predicts emotion (timeline sampling), and classifies the scene type using PyTorch (ResNet18).
4. **Cloud Migration:** The raw video and scene thumbnails are uploaded to Cloudinary.
5. **Database Sync:** The extracted metadata is securely upserted into MongoDB.
6. **Review & Organization:** The user views the processed clips in the Dashboard/Inspector, overriding AI decisions if confidence was low, and pushing final clips back to organized Cloudinary folders.

Using a full-stack architecture with a React frontend, a Flask API, and an asynchronous PyTorch/Celery pipeline, it turns hours of unorganized raw footage into an easily searchable, cloud-hosted library of clips, ready for final video editing."

**Examiner Question / Model Answer:**
*   **Q:** *Why did you choose Celery instead of processing the video directly in the Flask route?*
*   **A:** Video processing (extracting frames using FFmpeg, running ResNet inference) is extremely CPU/GPU blocking and takes seconds to minutes. Celery moves this intense workload to background workers while immediately returning a 200 OK + `task_id` to the user so they can poll for progress.

### PHASE 5: PIPELINE + ML/AI LOGIC (The Crown Jewel)

This is the most technically complex part of the project (`pipeline/processing/run_pipeline.py`). If you nail this section in your defense, you will succeed.

**1. Video Processing Pipeline (`process_video` function)**
When Celery fires the pipeline, these chronological steps happen:
1.  **Backup to Cloud:** Uploads raw video to Cloudinary immediately using `cloudinary_service.upload_video`.
2.  **Scene Detection:** Calls `find_scenes()` natively. This detects cuts, camera flashes, or extreme motion to chop the video into logical clips.
3.  **Frame Extraction & Thumbnailing:** For every scene detected, it finds the exact middle timestamp and uses OpenCV (`cv2.VideoCapture`) to extract a static JPG frame (`extract_frame`). This frame is then uploaded to Cloudinary as the display thumbnail.
4.  **Temporal Emotion Detection (`sample_emotions_over_scene`):**
    *   *Genius feature:* It doesn't just check one frame. It checks frames at `20%, 40%, 60%, and 80%` of the scene's duration.
    *   For each sample, it uses a HaarCascade (`haarcascade_frontalface_default.xml`) to see if a face exists. If there is no face, it instantly skips the heavy emotion logic.
    *   If there is a face, it runs `detect_emotion()`, logs the timeline, and calculates the dominant overarching emotion for the scene via simple voting algorithms.
5.  **Scene Type Classification (`scene_classifier.classify`):**
    *   The `MLClassifier` (`ml_classifier.py`) takes the middle thumbnail.
    *   It uses a custom PyTorch **ResNet18** model. It alters the fully connected layer (`model.fc`) to output the number of labels specific to your use case.
    *   It applies a Softmax to get probabilities.
6.  **Agentic Decision Layer (Confidence Fallback Logic):**
    *   If ML Confidence `>= 85%`: The AI automatically accepts it. `reviewed = True`.
    *   If ML Confidence is `< 60%` (or fails): The ML layer bails and asks `RuleBasedClassifier.py` (your fallback heuristic) to decide.
    *   If ML Confidence is Between `60-85%`: It asks the Rule-Based fallback for a "second opinion". If the Rule-Based and ML models *agree*, it is auto-approved. If they *disagree*, it flags `uncertain = True` to mandate a human to review it on the frontend.
7.  **Database Storage:** The giant combined JSON metadata dictionary is written locally to `scene_index.json` and actively pushed into MongoDB.

**Examiner Question / Model Answers:**
*   **Q:** *Why did you use a rule-based fallback instead of just using standard ML?*
*   **A:** Machine Learning models are rigid; if they encounter completely out-of-distribution data, they might confidently give the wrong answer. The rule-based heuristic classifier acts as an explicit set of guardrails. By combining them, I built an 'Agentic Decision Layer' that essentially mimics human uncertainty. If confidence is in a grey area, the AI asks a secondary system for agreement, and if they clash, it flags the footage for human review rather than destroying the integrity of the database.
*   **Q:** *Explain how your emotion detection works regarding the temporal timeline.*
*   **A:** Emotion isn't static over a 10-second clip. Therefore, my pipeline samples the video at 4 distinct intervals (20%, 40%, 60%, 80%). To optimize compute overhead, I first run an extremely cheap OpenCV face-detection cascade. If no face is detected, it skips emotion inference entirely for that frame. The scene's final dominant emotion is computationally decided by the majority voting result across those 4 timeline samples.

*   *Answer:* "Machine Learning models tend to possess 'confident ignorance' when given out-of-distribution data. To counter this, I implemented an Agentic Decision Layer within `run_pipeline.py`. The ML model acts as the primary decider. If its confidence score drops below a threshold (85%), it queries the Rule-Based Classifier. **Q5: "If I upload the exact same video twice, what does your system do?"**
*   *Answer:* "The `auto_organize_task` calculates an SHA-256 hash of the video's raw bytes before uploading or running any ML models. It checks MongoDB for an existing hash.
